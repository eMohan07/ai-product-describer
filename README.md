# AI Product Describer

[![Built with askThili](https://ask.thili.ai/api/v1/public/projects/w3dpd55vns/badge.svg)](https://ask.thili.ai/b/w3dpd55vns)

This project delivers a command-line interface (CLI) tool designed to assist small business owners in generating unique product descriptions. It leverages a custom GPT model, built from scratch and trained on existing product texts, to create creative and relevant descriptions for various inventory items.

## What you are building

**Goal.** You will build a command-line interface (CLI) tool that generates creative product descriptions by training a custom GPT model on examples of existing product texts.

**Done when.** The CLI tool successfully takes product details as input and outputs coherent, creative product descriptions generated by your custom GPT model, which has been trained on a corpus of example texts.

## Milestones

Tick these off as you go, and commit after each one.

- [x] **1. Collect a small corpus of product descriptions for a specific category.**  
      Hint: Focus on data collection and initial text cleaning.
- [x] **2. Implement the byte-pair tokenizer and generate embeddings for product text.**  
      Hint: Implement byte-pair encoding and create an embedding layer.
- [ ] **3. Build the causal self-attention mechanism and assemble the transformer block.**  
      Hint: Construct the causal self-attention mechanism and stack transformer blocks.
- [ ] **4. Train the GPT model using the collected product descriptions.**  
      Hint: Set up the training loop with a loss function and optimizer.
- [ ] **5. Implement a text generation feature that creates new product descriptions from a prompt.**  
      Hint: Implement text generation using sampling techniques.
- [ ] **6. Develop a CLI for users to input product details and receive generated descriptions.**  
      Hint: Use a library like `argparse` to build the command-line interface.

## Run it

You need Python 3.12 and git.

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # then choose a model; see the comments inside
python -m app.cli hello
pytest
```

Your work goes in `app/core.py` (one stub per milestone) and `tests/test_core.py`. The first tests pass already; they
check the plumbing.

## Settings and secrets

Model settings live in `.env`, which is ignored by git. **Never commit `.env` or paste a key into code.** If a key ever
reaches GitHub, treat it as leaked and make a new one.
